# CoCanvas 需求验证原型 (MVP)

> 找到你的队友，一起搞点有意思的事！

这是一个用于验证"大学生在线组队需求"的假门测试(Fake Door Test)原型小程序。

## 📋 项目背景

在正式开发完整的校园组队平台前，我们需要验证：
- 大学生是否真的存在在线组队需求？
- 他们是否愿意通过平台寻找队友？
- 哪些类型的组队最受欢迎？

## 🎯 验证目标

通过**5天验证周期**，收集以下核心数据：

| 指标 | 说明 |
|------|------|
| 总访问人数 | 有多少人打开小程序 |
| 点击"查看组队" | 用户兴趣点分布 |
| 点击"聊一聊" | 潜在交互兴趣 |
| 点击"加入组队" | 实际行动意愿 |
| 点击"发布组队" | 主动发布意愿 |
| 各类型组队点击率 | 哪类组队最受欢迎 |

**成功指标**：
- 点击率 ≥ 10%：需求强烈，进入功能开发
- 点击率 5%-10%：需细化定位
- 点击率 < 5%：重新审视方向

## 🚀 快速开始

### 1. 环境准备

- 微信开发者工具 (最新版本)
- 微信小程序账号 (或使用测试号)

### 2. 安装步骤

1. **克隆或下载项目**
   ```bash
   cd cocanvas-mvp
   ```

2. **用微信开发者工具打开项目**
   - 选择 `cocanvas-mvp` 文件夹
   - AppID: 使用你的小程序 AppID 或测试号

3. **开通云开发**
   - 点击工具栏的"云开发"按钮
   - 按提示开通云开发环境(免费版即可)
   - 记录环境ID

4. **创建数据库集合**
   
   在云开发控制台 → 数据库 → 添加集合，创建：
   - `analytics_logs` (埋点数据)
   - `user_feedback` (用户反馈)
   
   权限设置：开发阶段选择"所有用户可读写"

5. **上传云函数**
   - 右键 `cloudfunctions/reportAnalytics` 目录
   - 选择"上传并部署：云端安装依赖"

6. **编译运行**
   - 点击"编译"按钮
   - 在模拟器中预览
   - 使用真机调试进行测试

### 3. 发布体验版

1. 点击"上传"按钮，上传代码
2. 登录[微信公众平台](https://mp.weixin.qq.com)
3. 进入"版本管理" → 选择开发版本 → 提交审核或设为体验版
4. 生成体验版二维码，分享给目标用户

## 📊 功能说明

### 假门测试机制

本项目使用**假门测试(Fake Door Test)**方法：

| 功能 | 用户看到 | 实际行为 | 埋点记录 |
|------|----------|----------|----------|
| 浏览组队列表 | 20条真实感的组队卡片 | 展示本地假数据 | ✅ 页面浏览 |
| 点击查看详情 | 完整的组队信息 | 展示假数据详情 | ✅ 卡片点击 |
| 点击"聊一聊" | 弹窗"功能维护中" | 仅记录点击 | ✅ 按钮点击 |
| 点击"加入组队" | 弹窗"功能维护中" | 仅记录点击，引导反馈 | ✅ 按钮点击 |
| 点击"发布组队" | 表单填写 → "已发布" | 前端临时展示，不保存 | ✅ 发布意愿 |
| 用户反馈 | 反馈表单 | 真实保存到数据库 | ✅ 反馈提交 |

- 📚 学习小组

- 💼 创业项目
- 🎭 社团活动
- ❤️ 志愿服务
- 💻 实习项目
- 📝 其他

### 关键指标计算

```
总访问人数 = COUNT(DISTINCT openid WHERE event_name='app_launch')
查看详情次数 = COUNT(event_name='card_click')
点击"聊一聊"次数 = COUNT(event_name='button_click' AND button_name='chat')
点击"加入组队"次数 = COUNT(event_name='button_click' AND button_name='join_team')
点击"发布组队"次数 = COUNT(event_name='button_click' AND button_name='publish_team')

点击率 = (点击操作次数 / 总访问人数) * 100%
```

## 🔍 数据分析示例

验证结束后，重点分析：

1. **用户参与度**
   - 访问量 vs 点击率
   - 高峰访问时段
   - 用户停留时长

2. **需求验证**
   - 哪类组队最受欢迎？
   - 用户更倾向"加入"还是"发布"？
   - 反馈内容的共性

3. **用户画像**
   - 主要通过什么渠道进入？
   - 年级/专业分布（需在反馈表单中收集）

## ⚠️ 注意事项

1. **数据隐私**：严格保密用户数据，仅用于产品改进
2. **诚信原则**：在合适时机告知用户这是验证原型
3. **及时反馈**：对提交反馈的用户，后续功能上线时通知
4. **记录每日数据**：每天截图数据变化，方便后期分析
